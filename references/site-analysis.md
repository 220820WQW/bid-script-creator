# 目标网页分析与停止条件

本文件约束生成代码前的目标站点分析。所有请求方式、参数、字段、选择器和附件结构必须来自真实页面或响应。

## 栏目入口确认

1. 打开用户提供的目标网址；必要时使用可用的浏览器 MCP 校验。
2. 用户提供站点首页或上级页面时，从页面真实可见的导航栏、侧边栏、标签页、下拉菜单、更多栏目或分页入口进入指定栏目，禁止只凭 URL 猜测。
3. 用户提供列表页时，也要通过页面标题、面包屑、栏目高亮或列表内容确认与指定栏目一致。
4. 页面存在多个同名或近似栏目时，根据页面位置和内容选择；无法确定时询问用户。
5. 同一页面存在多个待采栏目，且栏目通过 JavaScript、标签页或按钮动态切换、浏览器地址栏 URL 不变时，可按照“动态栏目联调”规则执行。

## 动态栏目联调

1. 必须使用可用的浏览器 MCP 逐个点击用户指定栏目。
2. 每个栏目都要确认可见文本、选中或高亮状态，以及列表内容确实发生对应变化。
3. 必须确认每次切换触发的 XHR/Fetch 或其他数据来源与当前栏目一一对应。
4. 分别记录真实接口 URL、请求方式、栏目区分参数、分页参数和响应列表字段路径。
5. 切换后没有新请求时，继续确认数据是否来自首次响应、页面内嵌数据或前端缓存。
6. 禁止只分析默认栏目，也禁止根据固定 URL、参数名或代码猜测栏目关系。

没有可用浏览器 MCP，或联调后仍无法确认栏目与数据请求的一一对应关系时，必须询问用户。

## 列表页分析

1. 确认每条列表数据的详情链接、标题、发布时间分别来自哪个 DOM 元素或 JSON 字段；同时检查标题是否因字符长度限制以 `...`、`…`、`……` 等尾部省略标记截断，并通过详情页标题或稳定页面结构确认。
2. 检查用户指定页数范围内的列表链接去向，不得只抽查第一条就判定栏目是否可采集；未指定页数时按一页检查。
3. 多页采集必须操作下一页或检查真实分页请求，确认第一页、后续页和请求参数的变化规律。
4. 多个栏目必须逐一分析并比较结构。只有 URL、页码或接口参数不同而 DOM/JSON 字段一致时，后续复用同一解析逻辑；只有结构或字段确实不同才允许使用顶层 `t` 分支。
5. 指定范围内只要存在至少一个与用户目录网站 URL 同源的详情链接，就继续分析并生成同源采集逻辑，不得因外链占多数而放弃。
6. 指定范围内所有列表项均非同源时，不生成外链采集逻辑，并向用户说明没有可采集的同源详情链接。

## 详情页与附件抽样

1. 确认正文来自哪个 DOM 元素或 JSON 字段，禁止只确认详情页能够打开。
2. 按用户指定页数抽样同源列表项：采集一页时，在第一页随机抽取三条；采集多页时，每个指定页分别随机抽取三条；某页不足三条时检查该页全部可用同源条目。
3. 检查正文之外是否存在附件下载入口，并确认真实下载链接及其 DOM、JSON 字段、点击行为或附件接口。附件 URL 可能是动态接口、参数地址、无扩展名地址或重定向地址，不得只按 `.pdf`、`.doc`、`.docx`、`.xls`、`.xlsx` 等 URL 后缀或文件名特征判断。
4. 附件身份必须结合页面语义和真实行为确认，例如独立附件区、附件名称或“下载”文本、`download` 属性、明确的附件接口、点击后触发下载、响应 `Content-Disposition` 等。只要已经确认是附件下载链接，即使 URL 和文件名没有常见扩展名也必须采集；普通正文导航链接不得误判为附件。
5. 抽样发现额外附件时，记录附件容器、真实下载地址、是否为完整绝对 URL 及稳定提取规则；附件链接默认按同源处理，不分析或区分其域名。全部抽样均未发现时，禁止生成猜测性的通用附件遍历代码。
6. 正文通过 `iframe`、`object`、`embed` 展示 PDF 时，该文件属于正文，不受额外附件抽样限制；必须提取真实 URL，补全为绝对 URL，并转换为带“内容附件”等标识的 `<a>` 标签。
7. PDF URL 位于 JavaScript 调用或脚本字符串中时，先用 BeautifulSoup 定位正文或相关 `script`；只有无法直接提取参数时，才对局部内容使用 `re`。
8. 正文 PDF 与独立附件同时存在时全部保留，不得二选一。

## 数据来源确认

1. 列表或正文直接存在于响应 HTML 时，按 HTML 数据处理。
2. 数据来自 XHR/Fetch 时，记录真实接口 URL、请求方式、请求体、分页参数及响应字段路径。
3. 页面首屏源码没有数据但渲染后可见时，确认来自接口、内嵌数据还是前端缓存。
4. JSON 字段中包含 HTML 片段时，同时记录 JSON 字段路径和片段内部的真实 DOM 结构。
5. 详情正文来自独立接口时，记录接口 URL、所需列表字段、请求参数和正文字段；展示页 URL 与正文接口 URL 必须区分。

## 命中瑞数特殊处理

确认首次响应 202 与 Cookie、长 `meta[content]`、`$_ts` 脚本、固定外链 JavaScript 及二次 Cookie 请求等瑞数特征后，不得停止，也不得按普通逆向流程自行设计绕过代码：

1. 立即完整读取 `references/ruishu.md`。
2. 使用本机可用的浏览器 MCP 打开用户指定栏目。页面持续空白、无法正常加载栏目内容时才停止，并说明原因。
3. 页面正常加载时继续完成列表、详情、分页、字段和附件分析，生成阶段使用固定瑞数 Cookie 模板。
4. 直接请求返回 202 或需要本地 JS 计算 Cookie，不再构成停止生成的理由。

## 命中加速乐特殊处理

确认连续三次请求、前两次 521、`__jsluid_s`、两阶段 `__jsl_clearance_s` challenge 及第三次 200 等加速乐特征后，不得停止，也不得按普通逆向流程自行设计绕过代码：

1. 立即完整读取 `references/jsl.md`。
2. 使用本机可用的浏览器 MCP 打开用户指定栏目。页面持续空白、无法正常加载栏目内容时才停止，并说明原因。
3. 页面正常加载时继续完成列表、详情、分页、字段和附件分析，生成阶段使用固定 challenge、代理和 Cookie 模板。
4. 前两次请求返回 521 或需要 Node 执行 challenge，不再构成停止生成的理由。

## 命中阿里 acw_sc__v2 特殊处理

首次响应为 200 并返回 `acw_tc`，且 challenge HTML 同时具有 `textarea#renderData` 的 `l1/arg1`、显式写入 `acw_sc__v2` 的脚本和长混淆 `script[name^="aliyunwaf_"]` 时，不得停止，也不得按普通逆向流程自行设计代码：

1. 立即完整读取 `references/acw-sc-v2.md`，按其中的联合特征完成确认，禁止凭单一字符串误判。
2. 使用本机可用的浏览器 MCP 打开用户指定栏目。页面无法正常加载或持续超时时才停止，并说明原因。
3. 页面正常加载时继续完成列表、详情、分页、字段和附件分析，生成阶段使用固定 `compute_cookie()`、`get_cookies()` 及代理流程。
4. 直接请求返回 challenge HTML 或需要 Node 执行 `compute_cookie.js`，不构成停止生成的理由。

## 停止条件

1. 除三个特殊加密 reference 明确规定的流程外，发现其他逆向点时先调用本地适用 skill 分析；能够稳定还原为无浏览器依赖的单文件 Python 请求链时继续。
2. 依赖人工验证码、不可移植设备指纹、持续浏览器环境，或分析后仍无法稳定还原时，停止并说明具体停止原因。
3. 普通 HTML、简单 JSON 接口，或仅需替换 URL、页码、选择器、字段名的相似栏目，不属于停止条件。
4. 动态栏目无法完成浏览器联调或无法确认栏目与数据请求的一一对应关系。
5. 指定页数范围内不存在任何同源详情链接，或关键生成依据无法通过真实页面和响应确认
